本模块是 GPUI Kit 的多 crate 工作区，按职责分层组织：
- `crates/base`（gpui-base）：最底层，依赖外部 `gpui`/`gpui-fast`，实现 Dock、Input、Motion、Plot、Questionnaire、Resizable、Text 等基础行为与交互原语。
- `crates/component`（gpui-component）：基于 gpui-base 的 60+ 高级组件库（button、dialog、table、chart、input、theme 等），通过 `component-macros` 派生宏生成代码；可选启用 tree-sitter/syntect 语法高亮与 speech 语音输入。
- `crates/assets`（gpui-kit-assets）：通过 `build.rs` 扫描 `assets/icons/*.svg` 生成 `IconName` 枚举与内嵌字节数组，WASM 下走 reqwest 远程加载，native 下用 rust-embed 打包。
- `crates/shell`（gpui-shell）：脚本化应用运行时，暴露 `ShellRuntime`、`HostModule`、`Capabilities` 等公共 API，默认集成 QuickJS（rquickjs + quickjs-jit-stdlib）作为脚本引擎，并通过 feature `components`/`webview`/`gpui-fast` 选择性组合上层组件与 WebView。
- `crates/component-macros`：proc-macro crate，提供 `icon_named!` 与 `IntoPlot` derive，供 component 与 assets 在编译期生成图标枚举与绘图类型转换。
- `crates/fps`：GPU/内存/FPS 监控与 overlay，被 shell 按需启用。
- `crates/webview`：基于 wry 的跨平台 WebView 宿主（macos/linux 分文件实现）。
- `crates/story` / `crates/story-web`：组件故事展示应用（原生与 WASM 双入口）。
- `crates/kit`：测试工具与集成测试基础设施。

依赖方向自底向上：assets → base → component → shell；fps/webview 由 shell 可选引入；story 依赖 shell 与 component。feature flag（gpui-fast、components、webview、quickjs、tree-sitter-*、speech、inspector、decimal）控制各 crate 的可选能力，使同一套源码可构建最小 runtime、完整桌面应用或 WASM 包。
