脚本按职责平铺在 `script/` 下，无子模块划分，通过 shebang 指定运行时：
- Bun 脚本（`#!/usr/bin/env bun`）：`bump-gpui.ts`（从 Zed 源码生成并推送 `gpui-pre-*` 快照到 crates.io）、`check-gpui-pin.ts`（校验 workspace 中 `gpui-pre-*` 依赖为精确版本）、`sync-lucide.ts`（下载并校验 Lucide SVG 归档）。这些脚本直接操作 Cargo/TOML、crates.io API 和 GitHub API。
- Bash 脚本：`bootstrap` 根据 `OSTYPE` 分发到 `install-linux.sh`；`bump-version.sh` 驱动 `cargo set-version` + git tag 的发布流程；`install-linux.sh` 安装 Ubuntu 24.04 上的系统依赖。
- Node.js ESM 脚本：`normalize-website-frontmatter.mjs` 规范化文档 frontmatter。
- 可执行工具：`publish-crates`、`build-website-versions`、`snapshot-website`、`test-snapshot-website`、`run-story-macos`、`check-ai`、`check-ai-recipes`。
- 测试位于 `script/tests/`，分别用 Bun 和 Python 运行。
依赖方向单向向外：脚本读取仓库根目录（如 `import.meta.dir/..` 指向 repo root），不反向被业务代码引用。
